KAAL Spaces

Runtime profile switching for KAAL OS — four spaces, one system, instant adaptation

🎮

Gaming

Performance mode for gaming. Max CPU/GPU, low-latency audio, game launchers, DND.
CPU: performance
Audio Q: 64 samples (~1.3ms)
GPU: max power
Effects: off
Notifs: DND
💻

Development

IDEs, containers, terminal tools. Balanced power for long compile sessions.
CPU: schedutil
Audio Q: 256 samples
GPU: auto
Effects: on
Services: Docker, Podman
⚡

Power User

Full system access. All tools exposed, tiling WM, SSH, verbose logging.
CPU: schedutil
Audio Q: 128 samples
SSH: enabled
Services: Cockpit, sysstat
Notifs: all
🏠

Normal

Everyday computing. Clean desktop, daily apps, power saving, simple UI.
CPU: powersave
Audio Q: 1024 samples
GPU: auto
Effects: on
Services: minimal

How Space Switching Works

1
User triggers switch via kaal-space switch gaming (CLI), GUI card click, or auto-switch rule
↓
2
kaal-spaced D-Bus daemon receives SwitchSpace("gaming") call
↓
3
Pre-exit hooks run for current space (cleanup, save state)
↓
4
systemctl isolate kaal-space-gaming.target activates new space target
↓
5
apply-space.sh gaming reads /etc/kaal/spaces/gaming.conf and applies all settings (CPU, GPU, audio, services, desktop, environment, network QoS)
↓
6
Post-enter hooks run for new space (GameMode daemon, Docker startup, etc.)
↓
7
State updated: /run/kaal/current-space = "gaming", persisted to /var/lib/kaal/spaces/last-space
↓
8
D-Bus signal SpaceChanged(old, new) emitted → GUI updates card highlighting
↓
9
Desktop notification: "KAAL Space: Gaming — Performance mode for gaming"

Boot Flow

1
kaal-spaced.service starts at boot (after D-Bus, PipeWire)
↓
2
Reads last space from /var/lib/kaal/spaces/last-space
↓
3
Runs apply-space.sh to restore configuration
↓
4
Pre/post-enter hooks run → System is in the same space as last session
↓
5
Auto-switch daemon starts → monitors power state, active app, time of day
